# DriveMate 后台测试打印补丁

## 目标

James 在正式后台使用 TE344 300dpi、Windows 11、USB 进行调机试印，复用正式产品标签版式及浏览器打印窗口；测试结果与真实装运打印、收货和库存隔离。

## 建议确认的实现

- Label print 增加次级按钮 Test print，打开右侧面板。
- 从当前已确认装运范围选 SKU，显示名称、PN 和条码。默认每款 2 张，首轮选 3 SKU 共 6 张。
- 通用上限：最多 10 SKU，每款 1–5 张，每任务总计不超过 20 张；前后端均校验。重复 SKU 拒绝，范围外 SKU 拒绝。
- 标签保持 70×50mm、原条码内容和正文尺寸；在供应方行位置标明 TEST — NOT FOR STOCK，不在条码上覆盖水印。测试标签单独保管并作废，不用于商品贴标或收货扫码。
- 测试任务使用独立表 public.warehouse_test_print_jobs。现有 warehouse_label_print_jobs、打印确认 RPC、收货门槛及库存函数保持不动。客户端无法通过参数把测试任务转换成正式任务。
- 测试结果为 pending / printed / failed / cancelled，仅表示测试结果。关闭打印窗口后仍为 pending，由操作者检查实物后记录；打印对话框取消由操作者选择 cancelled。
- 保存服务器生成的不可变标签快照、申请数量、创建人/时间、结果记录人/时间及失败/取消原因。结果仅允许 pending→终态，同结果重试幂等，不同终态覆盖返回冲突。测试记录本身提供完整的创建及结果追溯，不向正式收货历史伪造打印事件。
- 同一请求标识去重；写入超时后通过查询原请求确认状态，不自动再次创建。测试记录列表保留待确认任务，刷新后可继续记录结果；再次实际试印创建新测试任务，保留原记录。
- 使用现有 warehouse_label_print 权限；admin、partner、warehouse_staff 可操作，trade/public 拒绝。浏览器直连表无权限；RLS 开启，仅由已鉴权的服务端接口访问。新表不提供客户端插入/更新策略。
- 面板与正式打印互斥：有待确认的正式打印任务时，先处理该任务再开始试印；试印面板未关闭时不能触发正式打印。换装运/范围时防止旧请求或标签作用于新对象。

## 边界

本轮不开发自动发现 USB 打印机、静默打印、打印机硬件回执或 QZ Tray。实际打印仍由 Windows 驱动完成。测试模式通过界面和服务端隔离，并非在正式任务上增加一个可绕过的前端标记。

开发需一份新增表迁移；先在本地验证。Production 迁移、推送、部署和创建真实试印记录分别在发布阶段明确授权。不改真实员工、货物、订单、库存、SMTP、DNS、GST、支付或环境变量。

## 验收

1. 当前 3 SKU×2 张恰好输出 6 页，页尺寸正确；每页测试标识可见，条码与源产品一致。
2. 正式标签输出不出现测试标识，现有数量及分页不变。
3. 测试 printed/failed/cancelled 后，正式任务数量、正式 printGate、收货、库存和运营 Dashboard 业务计数均不变。
4. 正式结果 API 拒绝测试任务 ID；测试结果 API 拒绝正式任务 ID。
5. 空选择、超限、重复 SKU、范围外 SKU、资料不全、无权限、CSRF、断网、超时、双击、刷新及切换装运均有明确结果。
6. 本地 Postgres 实际执行迁移并核对权限及隔离；SQL 文本检查或内存测试不替代此项。无可用本地数据库时明确列为待验，不执行 Production 代测。
7. 浏览器复验桌面及移动端，保留截图；硬件出纸、尺寸与扫码由 James 现场确认。
